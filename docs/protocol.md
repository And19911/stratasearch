# Разбор приложения «Поиск людей под завалом» (StrataSearch)

Источник: APK `kz.alphasafety.stratasearch` (разработчик Alpha Safety, Казахстан).
Разбор сделан дизассемблированием байткода (декомпилятор скачать не дали — писал свой мини-дизассемблер).

## 1. Общая картина

```
[Метка шахтёра] ~~радио~~ [Метка/прибор спасателя] ~~радио~~ [Шлюз в ящике + антенна Яги]
                                                               │ UART
                                                        [HC-08/HC-42 BLE модуль, hc01.com]
                                                               │ Bluetooth LE
                                                         [Планшет с приложением]
```

* Верхняя плата в ящике — радиочасть: микроконтроллер Microchip PIC + радиотрансивер, через u.FL → SMA на направленную антенну Яги.
* Нижняя плата — мост UART↔BLE на модуле HC-08/HC-42 (DD3). Он просто прозрачно передаёт байты.
* Приложение — обычный BLE-клиент к «прозрачному UART».

## 2. Bluetooth

| Параметр | Значение |
|---|---|
| Сервис | `0000FFE0-0000-1000-8000-00805F9B34FB` |
| Характеристика (RX/TX) | `0000FFE1-0000-1000-8000-00805F9B34FB` (notify + write) |
| Размер куска | ~20 байт (MTU по умолчанию), пакеты приходят **фрагментами** |

## 3. Формат пакетов

Общий вид: `8F EA <тип> ... CK_A CK_B`

Контрольная сумма: Fletcher-8 (как у u-blox UBX), считается **по всем байтам, включая заголовок 8F EA**:
```
a = b = 0
for x in bytes: a = (a + x) & 0xFF; b = (b + a) & 0xFF
CK_A = a, CK_B = b
```
Проверено на двух эталонных пакетах, зашитых в коде.

### Тип 1 — отчёт узла о слышимых соседях (входящий)

| Смещение | Поле |
|---|---|
| 0–1 | `8F EA` |
| 2 | тип = `01` |
| 3 | счётчик/ID пакета |
| 4 | служебный байт (не используется в UI) |
| 5–7 | адрес узла, 24 бита, big-endian; у байта 5 старший бит — флаг (маскируется `& 0x7F`) |
| 8 | байт статуса (битовые поля, в UI не выводятся) |
| 9 | N — число соседей |
| 10 + 4·k | адрес соседа k (3 байта, тот же формат) + RSSI (1 байт, signed, дБм) |
| конец | CK_A, CK_B |

Пример из кода: `8F EA 01 00 27 8A 14 25 06 01 00 46 54 BF C4 25`
→ узел `0x0A1425` (660517) слышит узел `0x004654` (18004) с RSSI −65 дБм.

Длина пакета: 12…256 байт. Адреса ≥ 1 000 000 отбрасываются.

### Тип 4 — периодический пакет шлюза (входящий) — **старое приложение его НЕ разбирает**

Найден в реальном логе (`logStrataSearch.txt`), идёт непрерывно, номер в байте 3 растёт на 1.
Длина всегда 43 байта, приходит кусками по 20 байт. Склеил 4 пакета подряд — контрольная сумма сходится у всех:

```
8F EA 04 0D 06 | 00 00 0C 00 00 0C 00 00 0C 00 00 00 00 00 0C 00 00 0C
                 00 00 00 00 00 00 00 0C 00 01 04 02 02 01 00 00 00 4D | 2F 40
```

| Смещение | Поле |
|---|---|
| 2 | тип = `04` |
| 3 | номер пакета (0x0A, 0x0B, 0x0C, 0x0D… подряд) |
| 4 | `06` (постоянно) |
| 5–39 | 35 байт данных (смысл пока неизвестен; меняется только байт 30: `0C`/`0F`) |
| 40 | `0x40 + номер пакета` (4A, 4B, 4C, 4D) |
| 41–42 | CK_A, CK_B |

Значит, старое приложение выбрасывает эти пакеты. Расстояние «−67 дБм / 17 м» в логе — старое значение из списка, на каждом новом пакете оно не обновлялось.

**Нужен ещё один лог**: записанный, когда рядом работает метка/прибор спасателя, чтобы увидеть пакеты типа 1 на реальном железе.

### Типы 6, 10, 11 — подтверждение конфигурации (входящий)
Байт 3 = ID отправленного конфиг-пакета → тост «Configuration message delivered».

### Тип 5 — конфигурационный пакет (исходящий) — **в старом приложении не вызывается (мёртвый код)**
12 байт + 2 байта CRC:
`8F EA 05 <id 1..255> <addr24, если addr<65536 — у старшего байта бит 0x80> 04 00 00 00 0A CK_A CK_B`
Перед ним отправляется один байт `FF` (видимо, «пробуждение»).

## 4. Логика поиска

1. Из всех пакетов типа 1 строится список строк «узел — сосед — RSSI — время».
2. Пользователь вводит два адреса (поля «узел» и «спасатель») или тыкает строку в списке.
3. Берётся **последняя** запись с этой парой, её RSSI переводится в расстояние.
4. Цвет фона результата: стало ближе/дальше по сравнению с прошлым значением.

### Формулы RSSI → расстояние (м), выводится диапазон `d−2 … d+2`

| Режим | Формула |
|---|---|
| В шахте без завала | d = e^(−(RSSI + 37.319) / 11.26) |
| В горной местности | та же, что «без завала» |
| В шахте с завалом | d = 10^((−53 − RSSI) / 38.57) |

Пример при RSSI = −65: без завала ≈ 11.7 м, с завалом ≈ 2.0 м.

Калибровочная таблица `distance.json` (RSSI → расстояние по каждому режиму) имеет приоритет над формулой, если есть точное совпадение RSSI. Есть «поправка точности» (Rx) на режим.

## 5. Состояние кода старого приложения

* Java, 2019–2020 г., minSdk 21 / targetSdk 29 — устаревшие разрешения Bluetooth (на Android 12+ работает только «по старой памяти»).
* Почти вся логика в одном классе `DeviceControlActivity` (~2000 строк байткода).
* Выбранный режим определяется **по цвету кнопки** (`getColor() == зелёный`), расстояние парсится обратно из текста на экране.
* Сборка фрагментированных BLE-пакетов — склейка «попарно наугад» (`buildCorrectPackage`), при потере куска данные теряются.
* Захардкожен адрес сервера разработчика `http://172.20.10.13:8080/rssi/json` и e-mail разработчика для отправки логов.
* Мёртвый код (отправка конфигурации, тестовые пакеты).
* Пишет лог в `logStrataSearch.txt` на SD-карту — **полезен нам**: там сырые пакеты с реального железа.
